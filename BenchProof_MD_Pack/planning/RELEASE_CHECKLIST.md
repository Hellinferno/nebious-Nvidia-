# Release and submission checklist

All implementation gates are pending. Feature freeze: 25 October. Internal submission: 28 October, 8:00 p.m. IST. Official dates/obligations are in [event requirements](../docs/01_HACKATHON_REQUIREMENTS.md).

## Product gate

- [ ] Actual qualifying NVIDIA model participates meaningfully at runtime on the recorded Nebius path.
- [ ] Candidate code executes in the tested isolated backend with pinned image.
- [ ] Accepted executable constraints are human-owned and mapped to protected checks.
- [ ] API/amount P0 repairs complete; any caller/idempotency P1 claims are implemented.
- [ ] Graph/impact context shows provenance and unknown/truncated scope accurately.
- [ ] Source/contract mismatches invalidate actions; P1 stale decisions are excluded if claimed.
- [ ] Repeated no-progress attempts stop; any P1 recovery is bounded and recorded.
- [ ] Independent invalid candidate rejection, correct clean result and limited/blocked result work.
- [ ] Mutation strength is separate; absent feature shows NOT_RUN, survivors/invalids stay visible.
- [ ] Real UI reads API records; reload/cancel/errors preserve evidence without duplicate actions.
- [ ] Export and preselected fresh replay work; three live hero runs passed.

## Integrity gate

- [ ] Candidate cannot edit constraints, evaluator/oracles, launcher, mutation templates or budgets.
- [ ] Hidden expectations/check code remain outside candidate execution; output is evaluated externally.
- [ ] Wrong/missing/forged result or required UNKNOWN cannot yield VERIFIED.
- [ ] Patch paths/size/base hashes and graph/check mappings are validated.
- [ ] Network/metadata denial, timeout/memory/output caps and remote termination are actually tested.
- [ ] Secrets absent from model inputs, source, runtime, browser build, logs and exports.
- [ ] Public intake remains curated; owner checks cover every run/event/patch/artifact route.
- [ ] Retry, verification, mutants and recovery obey original time/action/cost budgets.
- [ ] Tampered hashes/archives fail validation; SHA-256 is not described as an authenticated signature.

## Evidence and claims gate

- [ ] Selected suites/versioned truth/configuration are frozen before final measurement.
- [ ] R12/R6 trials and V12/V6/G8/F6/W8/M12 counts are kept separate.
- [ ] Every assigned failure/timeout/invalid output remains in the appropriate denominator.
- [ ] Same-model baseline uses fair information/budgets and common final evaluator.
- [ ] Actual result/latency/usage numbers link to immutable records, not target thresholds.
- [ ] Evaluated commit/configuration matches claimed deployed behavior; functional changes have affected reruns.
- [ ] Synthetic/small-sample, graph, oracle, mutant and provider limitations are explicit.
- [ ] No named product ranking/weakness claim without actual matched run artifacts.
- [ ] No guaranteed win, formal-proof, universal-safety or “all bugs” claim.

## Repository and access gate

- [ ] Public source contains the working release and actual top-level detectable license.
- [ ] Third-party model/SDK/image/asset notices and rights are reviewed.
- [ ] Exact locked install/setup works from a clean release clone.
- [ ] README/judge guide reflect implemented commands and supported features.
- [ ] Hosted incognito testing is free and independent of Ravi's private session.
- [ ] Persistent storage/backup restoration, worker supervision and stable URL are tested.
- [ ] Host/provider balance/expiry support the full judging period with reserve.
- [ ] Public bundles exclude hidden final evaluation truth until its intended release.

## Video and entry gate

- [ ] Genuine footage, accurate live/recorded labels, captions and duration below three minutes.
- [ ] Public video/demo/repository links work in incognito.
- [ ] Description, track, services/model, feedback, setup/testing instructions and live form fields are complete.
- [ ] Feature and result copy matches the final release; unresolved placeholders removed.
- [ ] Eligibility/registration/rights and required declarations are checked by Ravi.
- [ ] Entry is actually submitted, not merely saved as draft, by internal target if possible.
- [ ] Submitted-status confirmation, final copy, release hashes and links retained.

## After submission

- [ ] Recheck status/access on 29–30 October and follow organizer allowances for repairs.
- [ ] Keep free reviewer access through the period in event requirements, plus margin.
- [ ] Preserve source tag, deployment, evidence/backups and failed records.
- [ ] Continue future development separately from the submitted version.
