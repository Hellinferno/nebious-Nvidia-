# Product demonstration and recording script

Target 2:50, below three minutes. Record the built release only. This replaces the former ML-score narrative with the research-aligned engineering assurance journey.

## Timed sequence

| Time | Product action | Narration purpose | Evidence visible |
| --- | --- | --- | --- |
| 0:00–0:20 | Open synthetic service/task and candidate | “A patch can pass smoke tests and still violate an accepted contract.” | Fixture, task, source and live mode |
| 0:20–0:40 | Show pinned C-AMOUNT/C-API intent | State the exact behavior being checked | Required constraints/check mappings |
| 0:40–1:00 | Inspect impact on route/helper/worker | Explain why the changed helper affects another path | Graph/list, provenance and scope limits |
| 1:00–1:25 | Run trusted counterexample; reject shallow candidate | Show the missed failure rather than claim broad agent inferiority | Actual FAIL, input/property and check ID |
| 1:25–1:55 | Show real NVIDIA repair request/result and diff | Make runtime model contribution concrete | Model/provider metadata, approved diff |
| 1:55–2:20 | Fresh independent verification | Explain accepted checks and remaining limits | Required check table, verdict, runner/image |
| 2:20–2:35 | Show mutation strength or clean/rejected outcome | Show measured strength if P1 works; otherwise clear honest boundary | Actual counts or labeled NOT_RUN/clean |
| 2:35–2:50 | Download bundle and open replay manifest | “Review the exact checks and reproduce the decision.” | Manifest hashes, replay guide, source link |

If a live run exceeds available video time, show genuine captured segments with visible timestamps and disclose speed-up/cuts. Do not stage an invented tool run or animate a graph unrelated to recorded data. A recorded segment is labeled; the submission still needs a functional reviewer path.

## Numeric slots

Use only actual amount examples/check results and measured suite counts. Benchmark overlay, if useful, names R12/R6, evaluated commit and numerator/denominator. Avoid unsupported accuracy, saved-hours, dollar savings, competitor ranking or “all bugs” claims. If no final measurement exists, omit the overlay.

Mutation `killed / valid executed` is not repair accuracy. A hash manifest is not a formal correctness proof or authenticated signature. Graph coverage is limited to the declared scope.

## Recording checklist

- [ ] Three consecutive live rehearsals passed on the final configuration.
- [ ] Source, accepted contract, evaluator, image and model metadata are recorded.
- [ ] Real inference participates in the demonstrated repair; mock is absent.
- [ ] Clean/rejected/limited states are available for reviewer testing.
- [ ] No secrets, hidden benchmark truth or unauthorized private source is visible.
- [ ] Narration matches shipped P0/P1 capabilities and actual results.
- [ ] Captions and readable zoom support the key failure/diff/check views.
- [ ] Final duration, public link and incognito playback are checked.

## Outage procedure

Keep a genuine successful capture and immutable bundle ready. If a provider is unavailable, label replay footage and state the limitation in testing instructions; retain a functioning access route as required by the event. Never label saved evidence a new live call.

## Rehearsal review

Record run IDs, duration, failure point and fixes. Ask whether the user/problem is clear in twenty seconds, the model writes useful code, the rejection is independent, and the export explains scope. Remove optional screens before compressing the protected verification beyond comprehension.
